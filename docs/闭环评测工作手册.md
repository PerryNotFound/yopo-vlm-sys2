## 1. 环境激活指南

### 每次开新终端，按任务选择激活方式：

| 任务 | 激活命令 | 终端左边显示 |
|-----|---------|-------------|
| **跑 VLM / 评测 / 训练** | `conda activate base` <br> `source ~/YOPO-Rally-Whole/YOPO-Rally/.venv/bin/activate` | `(YOPO-Rally) (base)` |
| **跑 MPC / YOPO 算法** | `source /opt/ros/humble/setup.bash` <br> `cd ~/YOPO-Rally-Whole/YOPO-Rally` <br> `source install/setup.bash` | 无特殊标识（系统 Python 3.10） |
| **跑 ROS 话题 / RViz** | `source /opt/ros/humble/setup.bash` | 无特殊标识 |
| **启动 ROS-TCP-Endpoint** | `source /opt/ros/humble/setup.bash` <br> `source ~/YOPO-Rally-Whole/tcp_ws/install/setup.bash` | 无特殊标识 |

### 注意事项
- **不要在 conda base 环境里跑 ROS 节点**——Python 版本不对（3.13 vs 3.10）
- 跑 VLM 时必须激活 venv——因为有 torch、transformers 等包
- 跑 MPC 时不能激活 venv——因为 venv 的 Python 版本和 ROS 不兼容

## 2. 复现 M0 和 M1 的具体流程

---

### M0：无 VLM，纯 YOPO + MPC 避障

**目标**：纯传统规划器避障，不用 VLM。

#### 步骤 1：启动 ROS-TCP-Endpoint
```bash
source /opt/ros/humble/setup.bash
source ~/YOPO-Rally-Whole/tcp_ws/install/setup.bash
ros2 launch ros_tcp_endpoint endpoint.py
```
**等它显示 `Starting server on 0.0.0.0:10000`**

#### 步骤 2：启动 Unity
```bash
conda activate base
source ~/YOPO-Rally-Whole/YOPO-Rally/.venv/bin/activate

cd ~/YOPO-Rally-Whole/YOPO-Sim-Project
~/Unity/Hub/Editor/2022.3.62f3c1/Editor/Unity -projectPath . -force-glcore &
```
**Unity 打开后**：
1. 双击 `Assets/Scenes/EvaluationScene.unity`
2. 点顶部 **Play** 按钮

#### 步骤 3：启动 YOPO + MPC 算法
```bash
source /opt/ros/humble/setup.bash
cd ~/YOPO-Rally-Whole/YOPO-Rally
source install/setup.bash

ros2 launch diablo_ros_wrapper diablo_algorithm.launch.py
```
**等它显示 `yopo_node started`、`mpc_node started`**

#### 步骤 4：启动 RViz
```bash
source /opt/ros/humble/setup.bash
rviz2 -d ~/YOPO-Rally-Whole/YOPO-Rally/src/ros_pkgs/diablo_ros_wrapper/configs/visualize.rviz
```

#### 步骤 5：选目标点
1. RViz 顶部工具栏点 **"2D Goal Pose"**
2. 在地图上点目标点
3. **小车自动避障开过去**

---

### M1：YOPO + MPC + VLM 安全否决

**目标**：VLM 判断安全/不安全，如果危险就停止。

#### 步骤 1-3：和 M0 一样
- 启动 ROS-TCP-Endpoint
- 启动 Unity（点 Play）
- 启动 YOPO + MPC 算法

#### 步骤 4：启动 VLM 安全判断
```bash
conda activate base
source ~/YOPO-Rally-Whole/YOPO-Rally/.venv/bin/activate

cd ~/YOPO-Rally-Whole/yopo-vlm-sys2
python eval/vlm_m1_safety.py
```
**等它显示 `VLM model loaded!`**

#### 步骤 5：启动仲裁节点
```bash
conda activate base
source ~/YOPO-Rally-Whole/YOPO-Rally/.venv/bin/activate

cd ~/YOPO-Rally-Whole/yopo-vlm-sys2
python eval/m1_arbitrator.py
```

#### 步骤 6：启动 RViz + 选目标点
- 和 M0 一样

#### 测试 VLM 能不能识别危险
1. 在 Unity 里加一个蓝色 Plane（模拟水坑）
2. 等小车开过去
3. **看 VLM 终端**：会不会出现 `VLM: safe=False`
4. **看仲裁节点终端**：会不会出现 `→ VLM 说危险，停止`

## 3. 论文方向选择和创新点总结

---

### 论文方向（已定型）
**候选轨迹语义否决（Semantic Veto on Trajectory Candidates）**

### 核心切割线（三点）

#### ① 越野语义陷阱的视觉混淆
- **问题**：纯色块颜色歧义（黄沙↔枯草、棕泥↔树干、树影↔深色泥泞）
- **现象**：Qwen3-VL-4B 微调后准确率从 84% 降到 55-65%
- **原因**：微调数据是纯色块，泛化能力差
- **解决思路**：数据 v2（纹理增强）+ 原版 VLM 跑闭环

#### ② 离散否决 vs 正向融合的安全性差异
- **离散否决（M2/M4）**：VLM 只判断"安全/不安全"，否决不安全的轨迹
  - **优点**：保守，宁可错杀，安全性高
  - **缺点**：可能过度保守，导致所有轨迹都被否决
- **正向融合（M3）**：VLM 输出安全分数，融合到规划器代价函数
  - **优点**：平滑，不会突然停止
  - **缺点**：可能不够安全，危险轨迹权重降得不够

#### ③ YOPO-Rally 候选轨迹扇区稀疏性
- **问题**：YOPO 生成的候选轨迹只有 5-7 条，扇区很稀疏
- **现象**：如果所有候选轨迹都不安全，就没有安全的轨迹可选
- **失效边界**：次优也不安全——候选轨迹太稀疏，中间漏掉了安全的轨迹
- **解决思路**：M4（离散否决+回退）——所有候选都不安全时，小车倒回去，重新规划

### 实验方案（M0-M4 五组对比）

| 实验 | 说明 | 状态 |
|-----|------|------|
| **M0** | 无 VLM，纯 YOPO + MPC | ✅ 跑通 |
| **M1** | 帧级二值 VLM 否决（每帧判断安全/不安全） | ✅ 跑通 |
| **M2** | 候选轨迹离散否决（VLM 否决不安全的候选轨迹） | 待写 |
| **M3** | 正向融合（VLM 输出安全分数，融合到代价函数） | 待写 |
| **M4** | 离散否决+回退（所有候选都不安全时，倒回去重新规划） | 待写 |

## 4. 现有工作成果总结

---

### 已完成的工作

#### ① Unity 配置
- ✅ DepthCamera_ros 配置（深度话题 `/camera/depth/image`，10Hz）
- ✅ RGBCamera_ros 配置（RGB 话题 `/camera/color/image/compressed`，10Hz）
- ✅ EvaluationScene 配置（小车位置、相机位置）

#### ② VLM 模型
- ✅ Qwen3-VL-4B-Instruct 原版模型（4bit 量化）
- ✅ QLoRA 微调（900 帧数据集，3 epochs，loss 收敛 0.06-07）
- ✅ 离线评测（val 178 帧：基线 82.6%，微调 53.9%）

#### ③ 闭环评测
- ✅ M0：纯 YOPO + MPC 避障
- ✅ M1：YOPO + MPC + VLM 安全否决
- ✅ VLM 能识别蓝色水面（判断 safe=False）

### 关键发现
1. **微调不如基线**——纯色块颜色歧义导致泛化能力差
2. **VLM 推理慢**——每秒一次，小车看到危险时已经碾上去了
3. **VLM 能识别危险**——蓝色水面、黄色沙土都能正确判断

## 5. 能不能用 Unity 自带的插件添加水面？

---

**可以！** 不用手动加 Plane，用 Unity 自带的水系统。

### 方案 A：Unity 自带 Water System（推荐）

**步骤**：
1. **Window → Asset Store**——打开 Asset Store
2. 搜索 **"Water"**——找免费的水材质
3. **或者**：用 Unity 自带的 **Terrain** 系统
   - 选中 Terrain
   - Inspector 里 **Paint Texture**
   - 选一个**蓝色水纹理**
   - 在地面上"画"一个水坑

### 方案 B：用现有材质

**你已经有 Blue 材质了**——直接用就行：
1. 创建 Plane
2. 材质选 Blue
3. 调整位置和大小

### 方案 C：用 Asset Store 的免费水插件

**推荐**：
- **Unity Water**（免费）——真实水面效果，有波纹、反射
- **Water Material**（免费）——简单的蓝色水材质
